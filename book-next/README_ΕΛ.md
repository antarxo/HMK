# Γενικός συγγραφέας βιβλίων

Έκδοση **v0.1.0 — σταθμός υποδομής**.

Ο φάκελος αυτός είναι η παράλληλη δοκιμή μέσα στο repository `HMK`. Ο
παραγωγικός φάκελος `../book/` παραμένει ανέπαφος.

Η έκδοση αυτή γενικεύει την υπάρχουσα εφαρμογή συγγραφής χωρίς να αλλάζει το
σχήμα `pages-v1` του βιβλίου. Το υπάρχον βιβλίο «Γέννηση και διάδοση του ΗΜ
κύματος» περιλαμβάνεται ως πραγματική δοκιμή συμβατότητας.

## Τι περιέχει

- `Editor.html`: η τοπική εφαρμογή συγγραφής με ελληνικό UI.
- `index.html`: ο αναγνώστης και η εκτύπωση του βιβλίου.
- `book-core.js`: ο μοναδικός κοινός renderer σελίδων και στοιχείων.
- `book-core.css`: η κοινή τυπογραφία και σελιδοποίηση οθόνης/εκτύπωσης.
- `chapter_content.json`: το υπάρχον βιβλίο ως δείγμα και δοκιμή.
- `SCENE_PROTOCOL_ΕΛ.md`: η γενική σύμβαση για τις εφαρμογές σκηνών.
- `book-schema-v1.schema.json`: τεχνική περιγραφή του JSON.
- `legacy-baseline.html`: αντίγραφο του παλιού renderer, μόνο για regression
  έλεγχο. Έχει δύο δηλωμένες προσαρμογές διαδρομής ώστε ο παράλληλος φάκελος
  `book-next/` να επιλύει assets και σκηνές όπως ο παραγωγικός `book/`.
- `compare.html`: οπτικός και γεωμετρικός έλεγχος παλιού–νέου renderer με το
  ίδιο ακριβώς `chapter_content.json`.
- `REGRESSION_ΕΛ.md`: οδηγίες και κριτήρια του ελέγχου.
- `REGRESSION_DOM_REPORT.json`: αποθηκευμένο αποτέλεσμα του ελέγχου DOM.

Τα `legacy-baseline.html` και `compare.html` είναι διαγνωστικά εργαλεία. Δεν
ανήκουν στον μελλοντικό αυτόνομο Συγγραφέα.

## Τοπική χρήση

1. Άνοιξε το `Editor.html`.
2. Πάτησε **Αρχείο βιβλίου** και επίλεξε ένα JSON ή πάτησε **Νέο βιβλίο**.
3. Επεξεργάσου τη δομή, τις σελίδες και τα στοιχεία τους.
4. Πάτησε **Εξαγωγή βιβλίου (JSON)**.
5. Το εξαγόμενο JSON μπορεί να αντικαταστήσει το `chapter_content.json` δίπλα
   στο `index.html`.

Ο συγγραφέας λειτουργεί με άνοιγμα αρχείου και λήψη JSON, χωρίς backend. Αν ο
αναγνώστης ανοίξει απευθείας από `file://` και ο browser δεν επιτρέψει αυτόματη
φόρτωση, εμφανίζει επιλογέα αρχείου αντί να απαιτεί local server.

## Έλεγχος μέσα στο HMK

Για την πλήρη σύγκριση χρειάζεται απλός τοπικός HTTP server, επειδή δύο τοπικά
iframe δεν επιτρέπεται πάντα να διαβάζουν το DOM το ένα του άλλου:

```bash
python -m http.server 8000
```

Μετά άνοιξε:

```text
http://localhost:8000/book-next/compare.html
```

Το εργαλείο φορτώνει:

- αριστερά το `legacy-baseline.html`,
- δεξιά το νέο `index.html`,
- και στα δύο το ίδιο `chapter_content.json`.

Η `main` εφαρμογή και ο παραγωγικός φάκελος `book/` δεν αλλάζουν.

## Κεντρική αρχή

Ο συγγραφέας, ο αναγνώστης και η εκτύπωση δεν έχουν πλέον διαφορετικό renderer.
Καλούν όλοι το `book-core.js` και χρησιμοποιούν το `book-core.css`. Έτσι οι
αλλαγές σε γραμματοσειρές, περιθώρια, εικόνες, σκηνές, λεζάντες και αποστάσεις
έχουν μία μόνο πηγή αλήθειας.

Όλα τα κειμενικά στοιχεία διατηρούν πλήρη στοίχιση και αυτόματο συλλαβισμό. Οι
τίτλοι και οι ετικέτες δεν μετατρέπονται αυτόματα σε κεφαλαία.

## Βασική ορολογία UI

| Ελληνικός όρος | Τεχνικό κλειδί JSON |
|---|---|
| Σελίδα | `page` |
| Στοιχείο σελίδας | `item` |
| Σκηνή | `scene` |
| Πλαίσιο δραστηριότητας | `interactive_callout` |
| Σημείο πλοήγησης | `nav_anchor` |
| Διεύθυνση σκηνής | `singleSrc` |
| Θέση | `placement` |
| Πλάτος πλαισίου | `frameWidth` |
| Αναλογία πλαισίου | `aspectRatio` |

Οι τεχνικοί όροι παραμένουν στο JSON για συμβατότητα, αλλά το UI χρησιμοποιεί
ελληνική ορολογία. Η ορολογία θα βελτιώνεται στις επόμενες εκδόσεις.

## Σκηνές και σελιδοποίηση

Κάθε σκηνή πρέπει να δηλώνει ρητά `aspectRatio`, `sceneHeight` ή `viewport`.
Ο γενικός renderer δεν αναγνωρίζει ειδικά ονόματα εφαρμογών ή ειδικές διατάξεις.
Στο δείγμα οι δέκα υπάρχουσες σκηνές απέκτησαν ρητή αναλογία, ώστε να κρατήσουν
την προηγούμενη σελιδοποίησή τους.

Η αρχική κατάσταση μιας σκηνής καλό είναι να περιγράφεται πλήρως στο URL.
Για ελεγχόμενη κίνηση, αλλαγή κατάστασης και εκτύπωση εφαρμόζεται η σύμβαση
`book-scene-v1` που περιγράφεται στο `SCENE_PROTOCOL_ΕΛ.md`.

## Έλεγχος έκδοσης

Στο ενσωματωμένο βιβλίο ελέγχθηκαν:

- 28 σελίδες και 28 φύλλα A4,
- 293 στοιχεία σελίδας,
- 10 διαδραστικές σκηνές,
- κοινός πυρήνας renderer `0.1.0`,
- φόρτωση του ίδιου JSON σε συγγραφέα και αναγνώστη,
- δημιουργία προεπισκόπησης από τον κοινό renderer,
- έγκυρο JavaScript και JSON χωρίς σφάλματα εκτέλεσης.

Στο HMK integration probe ο έλεγχος DOM έδωσε ισοδυναμία 28 σελίδων, 293
στοιχείων και 10 σκηνών. Η πραγματική γεωμετρία ελέγχθηκε στον Chrome μετά το
legacy cleanup με ανοχή 0 px και δεν βρέθηκε μη εγκεκριμένη διαφορά. Το τελικό
PDF πέρασε με 28 πραγματικές σελίδες A4 και 10/10 στιγμιότυπα σκηνών.

Το δοκιμασμένο print path χρησιμοποίησε και στις 10 σκηνές το άμεσο same-origin
`window.getBookPrintSnapshot()`. Η πλήρης μετάβαση των εφαρμογών στο ουδέτερο
`BookScene` / `book-scene-v1` παραμένει επόμενος σταθμός πριν αποσπαστεί ο
Συγγραφέας ως ανεξάρτητη εφαρμογή.
